# 8.2 مؤجَّل (Deferred) — يستحق البناء بعد الإطلاق

---

## 8.2.1 Market Context Intelligence

### الفجوة الحقيقية

المستخدم يرى انخفاضاً بنسبة 12% ويسأل:

```text
هل السوق كله نزل؟ أم محفظتي أنا فقط؟
```

اليوم لا يستطيع Radareum الإجابة — لأنه لا يملك بيانات خارج المحفظة.

---

### التصنيف الصحيح للمشكلة

> **هذه فجوة بيانات (data gap)، وليست فجوة وكيل (agent gap).**

هذه التفرقة هي جوهر القرار. الاقتراح الأصلي عالجها بوكيل LLM منفصل — وهذا خطأ تشخيصي: الوكيل الإضافي لا يخلق بيانات غير موجودة.

الحل الصحيح:

```text
مصدر بيانات سوق (Market Data Source)
  ↓
Market Context Engine   ← محرك ذكاء عادي، حتمي، مثل بقية محركات Part 5
  ↓
EngineOutput            ← نفس الظرف (§5.0.6.1)
  ↓
Orchestrator (Part 2)
```

**لا وكيل LLM منفصل. لا استثناء معماري.**

---

### شروط ملزمة عند التنفيذ

```text
✅  مقارنة أداء المحفظة بحركة السوق في نفس الفترة
✅  فصل "أثر السوق" عن "أثر قرارات المحفظة"
✅  ذكر مصدر بيانات السوق وتاريخه

❌  توقع أسعار أو اتجاهات مستقبلية
❌  توصية بالشراء أو البيع أو إعادة التوزيع
❌  تفسير أخبار السوق كسبب مؤكد
```

قيود **Part 4** و **§7.7 · Guardrail 2 — Prediction** تبقى سارية بالكامل. المحرك يشرح **ما حدث**، لا **ما سيحدث**.

---

### لماذا مؤجَّل

يتطلب مصدر بيانات خارجياً (تكلفة + موثوقية + تحديث) لا يخدم الإطلاق الأول. القيمة حقيقية لكنها ليست على المسار الحرج.

---

## 8.2.2 Security Intelligence Engine

### النطاق

محرك يركّز على:

```text
Token approvals — الصلاحيات الممنوحة للعقود
Contract interactions — التعامل مع عقود غير موثوقة
Anomaly-driven security signals — إشارات مبنية على الشذوذ
```

---

### لماذا مؤجَّل

البيانات اللازمة (approvals + بيانات العقود) **غير مزامَنة اليوم**. بناء محرك أمان فوق بيانات ناقصة ينتج إنذارات كاذبة — وهي أسوأ من غياب الميزة، لأنها تُفقد الثقة في كل تنبيه آخر.

---

### الجسر المؤقت

حتى ذلك الحين، الأسئلة ذات الطابع الأمني تُوجَّه إلى **`detect_anomalies`** (§3.7 · المجموعة الحادية عشرة) مع الإفصاح عن حدود البيانات المتاحة.

عند توفر بيانات الـ approvals يُسجَّل هذا المحرك كـ Module كامل ضمن Part 5 بنفس الـ Template الموحّد.

# 8.3 مرفوض حالياً (Rejected) — مع الأسباب

---

## 8.3.1 Hierarchical Chief Agent + 7 Specialist LLM Agents

### الاقتراح

```text
Chief Agent
  ├── Performance Agent
  ├── Flow Agent
  ├── Portfolio Agent
  ├── Risk Agent
  ├── Trading Agent
  ├── Network Agent
  └── Counterparty Agent
```

كل وكيل نموذج لغوي مستقل، والـ Chief ينسّق بينهم.

---

### القرار

**مرفوض.**

---

### الأسباب

**1. القدرة مغطاة بالفعل**

```text
التنسيق          →  Orchestrator (Part 2)
فهم النية        →  Intent Engine (Part 2)
اختيار الأدوات   →  Tool Planner (Part 2)
التحليل المتخصص  →  محركات Part 5 الحتمية (Modules 01–09)
سطح أدوات موحّد  →  Tool Catalog (Part 3 §3.7)
```

الاقتراح يعيد بناء طبقة موجودة — لكن بنموذج لغوي بدل كود حتمي.

---

**2. يضاعف التكلفة والزمن**

```text
اليوم:      استدعاء سردي واحد لكل طلب مستخدم
المقترح:    1 (Chief) + N (المتخصصون) استدعاءات

الزمن يتراكم تسلسلياً عند أي اعتماد بين الوكلاء
```

هذا يناقض مباشرة **§7.10.1 · Cost** (الهدف: استدعاء سردي واحد) و **Bundles** (Part 3 §3.9–§3.10) التي وُجدت أصلاً لضبط التكلفة.

---

**3. يخلق تناقضات بين الوكلاء**

محركان حتميان على نفس المدخلات لا يتناقضان. نموذجان لغويان على نفس المدخلات **قد يتناقضان** — فيرى المستخدم رأيين مختلفين في رد واحد، ولا يوجد مصدر حقيقة يفصل بينهما.

---

**4. يكسر الحتمية**

**§7.10.1** يشترط: نفس المدخل ⇒ نفس المخرج. استبدال محرك حتمي بوكيل LLM يجعل هذا الشرط غير قابل للتحقق، ويكسر **§7.10 · Consistency** معه.

---

**5. الفلسفة الأساسية**

> **الـ LLM يشرح، ولا يحلّل.** (Part 5 §5.0)

سبعة وكلاء تحليل هو انقلاب على هذا المبدأ، لا امتداد له.

---

## 8.3.2 Per-Agent Private Memory

### الاقتراح

ذاكرة خاصة لكل وكيل متخصص.

---

### القرار

**مرفوض.**

---

### الأسباب

```text
خطر التناقض      →  ذاكرتان قد تحملان "حقيقة" مختلفة عن نفس المحفظة
صعوبة التتبع     →  عند رد خاطئ، أي ذاكرة السبب؟
لا مصدر حقيقة    →  لا توجد جهة تحسم الخلاف بين الذاكرتين
```

**الذاكرة تبقى مركزية** كما هي معرَّفة في **Module 10 §5.164 — Agent Memory** ([`05-10-agent-architecture.md`](./05-10-agent-architecture.md)).

## 8.3.3 Tax / DeFi / NFT / Whale-Behavior Agents

### القرار

**مؤجَّل بلا جدول زمني** — ولا يُبنى أياً منها كوكيل.

---

### السبب

هذه المقترحات **توسّع نطاق البيانات، لا الذكاء**:

```text
Tax    →  يحتاج تاريخ تكلفة موثوقاً + قواعد ولاية قضائية
DeFi   →  يحتاج مراكز البروتوكولات (LP · staking · lending) مزامَنة
NFT    →  يحتاج تسعير NFT وملكية موثوقة
Whale  →  يحتاج بيانات على مستوى السلسلة خارج محفظة المستخدم
```

المشكلة في كل حالة هي **غياب بيانات مزامَنة وموثوقة**، لا غياب طبقة تفكير. وقد نصّ **§5.0.5 · Extensibility** أصلاً على أن التوسعة تتم بإضافة **Intelligence Module** جديد — لا وكيل جديد.

يُعاد النظر **فقط** عندما تكون البيانات الأساسية مزامَنة وموثوقة.

---

# 8.4 Re-Evaluation Trigger

القرار أعلاه ليس أبدياً. يُعاد فتح ملف **Multi-Agent** إذا — وفقط إذا — تحقق أحد الشرطين:

```text
1.  سطح الأدوات تجاوز ~30 أداة
    عندها يصبح اختيار الأداة نفسه مشكلة تصنيف تستحق تقسيماً

2.  الوكلاء صاروا مطالبين باتخاذ قرارات مستقلة
    لا مجرد تحليل وشرح
    (مثال: تنفيذ إجراء، أو التفاوض بين أهداف متعارضة)
```

اليوم: سطح الأدوات **إحدى عشرة أداة** (Part 3 §3.7 + §7.4.1)، والوكيل **يحلّل ويشرح ولا يقرر**.

كلا الشرطين غير متحققين. القرار يبقى: **بنية واحدة، محركات حتمية، استدعاء سردي واحد.**
